# 日序 Node MCP 包

本地 stdio → 日序远程 `/mcp`（Streamable HTTP）。仅转发工具发现和工具调用，不复制业务逻辑、不保存 Key、不自动重试写操作。服务端按成员授权执行；OAuth 接入继续可用。

## 准备

1. 使用 Node.js 22 或更高版本。
2. 日序网页打开「AI 连接 → 通过 Node 连接」，填写名称、选择能力并生成 Key。默认选择查询和本人草稿，其余能力需明确选择。
3. Key 默认隐藏，仅在本次创建后可取用。自行点击「复制 Key」或「显示 Key」，用本地编辑器保存为仓库外、仅本人可访问的 UTF-8 纯文本文件，文件只含 Key；允许末尾换行。不要将密钥交给模型、粘贴进终端命令或写入日志。
4. 在 `packages/mcp-node` 目录运行 `npm pack`，将新版 `daily-flow-mcp-0.1.0.tgz` 放到使用 Codex 的电脑上。旧包不支持文件引用；此包尚未发布到 npm，请勿使用同名公共包。
5. 在网页填写本地包和密钥文件的绝对路径，复制生成的 Codex 配置。网页不会读取或创建本机密钥文件。关闭或刷新页面后无法再取回 Key，忘记时需生成新 Key；Key 持续有效直到成员撤销。

## Windows Codex 接入

网页生成的配置只包含本地包路径、服务地址和密钥文件路径，不包含 Key 正文。服务地址默认是当前站点的 `/mcp`；如果 Codex 所在电脑无法访问这个地址，请改为同一日序服务可访问的 HTTPS 地址或 `/mcp` 地址。`DAILY_FLOW_URL` 指定 Node 包要连接的远程服务，Key 会发送到这个地址，请核对后再复制配置。

将片段加入 Windows 用户级 Codex 配置 `%USERPROFILE%\.codex\config.toml`；已有同名区块时替换而非重复追加。重启 Codex，使用 `/mcp` 查看连接，再请 Codex 使用日序工具列出项目，进行不修改数据的连接测试。OAuth 仍可用；若配置两条日序连接，建议只启用其中一条以免工具重复。

```toml
[mcp_servers.daily_flow_node]
command = "cmd"
args = ["/c", "npx", "--yes", "--package=C:/tools/daily-flow-mcp-0.1.0.tgz", "daily-flow-mcp"]

[mcp_servers.daily_flow_node.env]
DAILY_FLOW_URL = "https://team.example.com/mcp"
DAILY_FLOW_API_KEY_FILE = "C:/Users/你的用户名/.daily-flow/member.key"
```

示例路径需换成实际存放位置。路径中的 `~`、`%USERPROFILE%` 和 `$HOME` 不会展开，请填写绝对路径；路径含空格或中文可以使用。首次使用 npx 可能需要联网下载依赖。

## 配置与行为

- `DAILY_FLOW_URL`：日序源地址或 `/mcp` 地址；远程必须 HTTPS，本机 localhost/127.0.0.1/IPv6 回环允许 HTTP。拒绝地址中的账号、查询参数、片段和其他子路径。
- `DAILY_FLOW_API_KEY_FILE`：密钥文件的绝对路径，Node 包仅在启动时读取。文件缺失、不可读、为空或内容格式错误时拒绝启动，不输出文件内容，也不自动回退。
- `DAILY_FLOW_API_KEY`：仍支持通过环境变量传入。若选择此方式，由用户在模型工具之外通过可信启动环境预置，并确认客户端确实将该变量传入 Node 进程；不要在 MCP 配置、聊天或命令中写出实际值。不保证不同客户端自动继承环境，无法确认时使用文件引用。
- 两种来源必须且只能配置一种，即使其中一个值为空也不能同时设置。缺少来源或来源无效时明确失败，避免使用错误身份。
- Key 只放在 `Authorization: Bearer …` 头，不放 URL，不向重定向地址传递。修改文件或环境变量后需重启 MCP 进程。
- 工具名称、参数、输出 schema、结果、错误及服务端 instructions 保留。工具列表每次向服务端查询，不缓存已撤销的授权能力。
- 写入沿用原 `operationId`，结果不确定时只允许以相同标识重试；业务版本冲突需要成员新的处理指令。
- 连接关闭或进程收到 SIGINT/SIGTERM 时关闭两侧连接。stdout 只写 MCP 消息，诊断写 stderr 且不包含密钥正文。
- 撤销通过日序网页完成，随后工具列表、调用和旧回执重放均被拒绝。

文件引用只防止意外把密钥拼入配置和命令，并非本机权限隔离：密钥文件仍是明文，拥有相应文件或环境读取权限的模型工具仍能取得密钥。不要将文件放入代码仓库或共享目录；不得让模型通过读文件、输出环境变量或检查请求头来验证真实密钥。

## 从旧配置迁移

1. 获取支持文件引用的新版包。自行将现有 Key 保存到仓库外文件，不让模型读取旧配置或录入密钥。
2. 在用户级 MCP 配置中删除含正文的 `DAILY_FLOW_API_KEY`，改为 `DAILY_FLOW_API_KEY_FILE` 路径，并确保启动环境没有同时传入旧变量。此改动不撤销现有授权。
3. 重启客户端，调用 `list_projects`，再到网页检查只读查询结果。项目列表为空也算成功；不要以文件存在或进程启动代替认证验证。
4. 若 Key 曾进入聊天、日志或仓库，改为新建 Key、完成上述验证后撤销旧 Key；单纯移动旧 Key 不能消除已经发生的泄露。不要自动撤销其他连接。

## 验证

在应用根目录构建服务后运行 `node node_modules/tsx/dist/cli.mjs --test tests/mcp-keys.test.ts`；测试使用隔离数据库、临时 Key 和真实 MCP stdio 子进程到 HTTP 服务，验证文件/环境变量读取、配置错误、输出脱敏、写入、幂等、权限与撤销。网页流程通过 Playwright 验证默认隐藏、手动显示/复制、配置不含密钥、路径错误和连接撤销；不读取真实凭证，不操作生产。
