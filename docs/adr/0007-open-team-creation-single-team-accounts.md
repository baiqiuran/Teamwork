# 单站多团队，公开创建与邀请加入分离

2026-09-21 确认：同一个站点支持多个相互隔离的团队，创建团队入口持续开放，不因已有团队而关闭；加入已有团队仍须邀请。“开放注册”指创建新团队，不是允许陌生人直接加入现有团队。为保持账号归属和登录流程简单，邮箱全站唯一，一个账号只属于一个团队。

本决策已接受，尚未实现；本轮仅记录术语和决策，不修改业务代码、不提交、不发布。

## 已确认边界

- 创建团队不再要求本机访问或引导密钥，也不设置“已有团队就禁止创建”的条件；创建者同时注册账号，成为该团队首位成员。不增设审批或开站口令，保留现有来源校验、密码规则和频率限制。
- 团队名称全站唯一。去掉首尾空格、统一全半角、忽略英文字母大小写后判重；名称中间的空格保留。重名时提示换名，不能凭已有团队名称直接加入。并发创建也不能产生重复名称。
- 邮箱全站唯一；已有账号不能再创建或加入其他团队，需要另一个邮箱注册。登录仍使用邮箱和密码，不增加团队选择器。
- 邀请仍为七天有效、单次使用、由生成者撤销尚未使用的邀请；本次不延长有效期、不改为可复用、不复活旧邀请。邀请只能使新账号加入邀请所属团队。
- 不新增管理员角色、成员停用或移除、团队切换、成员转移、团队改名功能；创建团队不赋予额外管理员权限。接受目前没有产品内停用手段这一边界。

## 数据与权限

继续使用现有 SQLite 和模块化单体，不引入每团队独立部署、独立数据库文件或子域名。已登录请求的团队由服务端根据账号确定；匿名邀请和公开读取分别根据有效邀请、分享凭据确定范围，不能信任前端传入的团队标识作为授权依据。

团队隔离覆盖成员列表、日报、项目、任务、附件、邀请、分享以及 MCP 查询、写入和操作记录。按对象 ID 访问、列表筛选及跨对象关联都必须检查所属范围，不能只在页面上隐藏其他团队的数据。公开链接仍允许持链接者免登录访问，但只能返回该链接授权的团队、目标、日期与模块内容；不新增公开成员列表。

原有成员、工作记录及其关联完整归入原团队，不清空或重建业务数据。迁移与发布仍遵守既有一致快照和配套恢复原则，不用旧程序直接写升级后的数据库。

本决策调整 [ADR 0001](0001-modular-monolith.md) 中“保留原表及 HTTP 契约、避免迁移”的适用范围，保留其单限界上下文、模块化单体与事务原则；[ADR 0002](0002-member-authorized-mcp-operations.md) 和 [ADR 0004](0004-member-key-node-mcp.md) 的成员授权不因此扩展到其他团队。

## 本轮配套交付

- `/members` 展示当前团队的成员列表，邀请管理移至 `/invitations`；保留对外的 `/join` 邀请路径。
- 列表显示姓名、加入日期和最近一次已提交日报的日期；未提交者显示“尚未提交”，按姓名排序。不展示邮箱、近七天提交数或活跃度排名。
- 清理前端及会显示给用户的后端提示：去口号、改晦涩措辞、统一必要称呼；保留确有用途的 Codex、MCP 名称以及真实命令和配置。不重做布局、不把技术设置隐藏为新交互、不新建全站文案框架、不批量替换测试选择器。
- 功能与文案一起交付、分块验收；同步调整受影响的测试。必须验证创建多个团队、重名与邮箱冲突、邀请加入、成员列表、旧数据迁移，以及两个团队之间的网页和 MCP 越权访问；前端改动需实际浏览器验收。记录决策不代表这些验证已经通过，也不代表授权生产发布。

## 取舍

未选择每团队一个部署，因为需求是同一站点持续接纳新团队；未选择一个账号加入多个团队，以避免增加团队切换和多重成员资格。长期邀请和公开加入已有团队均不属于此次开放注册的含义，因此维持原邀请规则。

公开创建团队且暂不提供停用功能，会保留垃圾注册与资源滥用风险；频率限制只能缓解，不能消除。后续不能为了“恢复单团队默认行为”而再次自动关闭建团队入口，也不能将未选择的审批、停用或多团队账号功能视为已获批准。
