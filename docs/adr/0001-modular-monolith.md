# 在单一限界上下文中采用 DDD 模块化单体

日序的日报、项目任务和公开分享共用同一套工作进展语言，且提交日报时创建任务、更新状态和保存回执必须原子完成，因此选择一个限界上下文内的模块化单体。领域层表达规则与状态转移，应用层通过仓储端口编排同步事务，SQLite 和本地附件由基础设施实现，HTTP 与 React 作为交互入口。

保留现有 SQLite 表及 HTTP 契约，避免架构调整变成数据迁移。成员、日报、项目任务、分享是上下文内的业务模块，并非四个独立微服务；审计记录也不等于事件溯源。文件写入不能参与 SQLite 事务，上传失败时由应用用例协调补偿删除，公开附件始终通过所属日报版本与分享范围重新鉴权。
