# 以成员授权 Key 接入本地 Node MCP 包

2026-09-20 用户要求 MCP 支持授权 Key，并明确选择通过 npx 启动本地 Node 包、配置服务地址和 Key。扩展 ADR 0002 的 OAuth 接入：新增成员可命名、分项授权、单独撤销的 Key，复用同一远程 MCP 入口、成员业务权限、操作回执和审计，本地包只负责 stdio 与远程协议转接。

Key 持续有效至撤销，这让本地配置不需要 OAuth 回调和刷新流程，代价是持有者在撤销前可以持续使用已授予能力。原先仅创建时交付、只保存摘要的约定，由下述 2026-09-24 回看决定调整。旧版 Key 丢失或权限变更时，成员先创建新 Key，并通过只读查询确认新连接可用，再撤销旧 Key。新旧 Key 在过渡期间分别按各自授予的能力生效，避免先撤销导致连接中断；失败时成员可重试或主动撤销新 Key，不自动撤销旧 Key。不提供团队共享超级凭证，不让 Key 签发其他凭证；现有 OAuth 短效访问凭证与轮换保持原行为。

2026-09-24 用户确认密钥引用调整的防护边界：防止密钥正文意外进入模型上下文、生成配置、拼接命令、日志及认证验证输出，真实密钥由成员在模型工具之外录入。环境变量或本地文件引用不构成本机权限隔离；接受拥有相应环境或文件读取权限的模型工具仍可能取得密钥，本次不引入独立凭证代理或进程权限隔离。

接入以本地密钥文件为主，生成配置通过 DAILY_FLOW_API_KEY_FILE 引用仓库外文件的绝对路径，保留已有环境变量读取方式，避免依赖不同客户端的环境继承行为；两种来源同时配置或文件无效时拒绝启动，不自动回退。网页首次交付默认不渲染 Key 正文，成员主动复制或显示后手动保存；已有 Key 不强制重新签发，不自动修改真实客户端配置或撤销连接，已进入聊天或日志的 Key 应另行创建新 Key、验证后撤销旧 Key。

用户已确认按此范围实施，认证协议和 OAuth 行为不变。验证仅使用隔离账号与临时 Key，覆盖文件及环境变量的真实 stdio 到 HTTP 认证、无效配置、撤销、权限与团队隔离、输出脱敏和浏览器回归；不读取真实凭证，不操作生产。实施及实跑结果另记于 Node 本地 MCP 规格。

2026-09-24 用户进一步确认跨登录、跨设备回看：新 Key 保留鉴权摘要，并使用服务器独立文件主密钥进行 AES-256-GCM 认证加密。每次回看只允许本人的有效网页会话，复核团队、连接类型与撤销／删除状态；不增加二次密码验证，MCP／OAuth Bearer 不能替代会话。选择服务器可解密而非一次性交付或浏览器缓存，是为了让返回和隐藏不等于丢失 Key；这不是端到端加密，取得本人会话也可能取得长期凭证。正文默认隐藏，仅主动显示／复制时临时获取，不进入列表、历史、日志或客户端配置。撤销阻止后续回看，不承诺擦除已复制的副本。

v11 只为凭证增加可空密文，不为旧摘要伪造正文或强制换钥。授权、摘要、密文原子创建，任何加密／存储失败均拒绝签发。主密钥不自动生成或替换，缺配置时新签发和回看明确不可用，原有摘要认证和 OAuth 仍可用；配置无效安全拒绝启动。主密钥须在仓库外单独保管、独立备份，与对应数据库配套恢复；丢失后不能靠重新生成恢复旧密文。具体文件格式、封装与配置见 [MCP 手册](../mcp.md)。
