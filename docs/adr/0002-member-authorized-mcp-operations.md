# 通过成员分项授权开放 MCP 自动操作

日序保留网页，并为团队成员增加远程 MCP 入口，首个验收客户端为 Codex。成员分别授予查询、自有草稿、日报提交、任务创建与状态更新、公开链接管理能力；默认仅选择查询和草稿，其余能力经成员选择后可自动执行，不要求每次回到网页确认。授权始终受现有成员权限、日报日期窗口、版本与公开范围规则约束，并可由成员撤销。

选择持续的分项授权，是为了让 AI 完成“整理工作到提交日报、更新任务”的完整流程，同时由成员控制可代办的范围；没有选择只读接入或逐次人工批准。公开链接必须明确目标、日期与模块，关闭仅限生成者；项目管理、邀请和附件文件传输仍在网页完成。

这是 2026-09-16 设计讨论中已确认的产品边界。成员授权持续有效直到主动撤销；版本冲突停止并等待成员新指令，不自动覆盖。凭证实现及最终设计记录于工作区 `.scratch/daily-flow-mcp/design.md`。

2026-09-17 补充确认：项目或任务关联不明确时返回候选项询问成员；未要求关联的内容可作为临时工作保存。持续授权不赋予 AI 猜测业务对象的权利。

2026-09-17 用户确认整体方案收口：网页与 MCP 在同一服务中共用应用用例和资源所有者，沿用 Nest、React、SQLite，通过 HTTPS、Streamable HTTP 与成员 OAuth 授权接入。授权、操作回执和独立状态事件的持久化需要兼容迁移；实现细节在后续规格中确定。本决策已接受。

2026-09-17 实施：采用同服务协议入口、框架无关授权及写入编排、成员级幂等回执和同事务审计，复用原业务用例。为保留重试确定性，成功回执不自动清理；为避免凭证长期暴露，持续授权配合 15 分钟访问凭证与刷新轮换。独立任务事件通过显式迁移解除日报关联非空约束，回退必须恢复匹配的旧备份。实际 Codex 与隔离验证记录见 MCP 手册；公网部署尚未验收。
