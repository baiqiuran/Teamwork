# 查询进展

查询团队业务内容需要 `progress:read`。私人草稿的读取另需 `drafts:write`，只能读取本人内容。

- 团队完整已提交日报：用 `list_diaries`。即使按项目筛选，命中后仍保留完整日报，不应称为“仅该项目的进展”。
- 单个项目或任务的进展：先用 `list_projects` / `list_tasks` 解析目标，调用 `query_progress`；根据结果 `entryIds` 仅归集匹配条目。
- 当前项目、任务详情：用 `get_project`、`get_task`。任务历史用 `list_task_events`；历史日报状态是提交快照，不代表任务当前状态。
- 成员候选用 `list_members`；未提交日报的成员也可能在名单中。缺少日报不等于没有工作。

先确定日期范围与筛选对象，再持续传回 `nextCursor`，直到为空。每次保留原筛选条件；列表默认 20 条，最多 50 条。用户要求完整汇总时不能只取第一页；如果主动限制了范围或未读完，应说明覆盖范围。

`summary` 表示摘要，`truncated` 表示裁剪，需完整事实时通过 `get_diary` 分段续读。项目进展虽然用完整日报详情补全，但最终只引用所选项目对应条目。内容或筛选变更导致游标冲突时，重新开始该次查询，不拼接新旧页。

汇总区分“已提交内容”“任务当前状态”和“本人私人草稿”，保留日期、成员及项目归属；只使用实际返回的记录，不根据空结果推断成员没有工作或凭空生成阻塞原因。
