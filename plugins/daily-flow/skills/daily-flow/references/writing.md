# 日报与任务

## 本人草稿

需要 `drafts:write`。用户未指定已有日报时使用 `create_draft`，避免覆盖同一天的其他草稿。每个工作条目生成独立 UUID；正文使用用户提供的事实，每条最多关联一个项目及该项目下的任务。未要求关联的内容可保留为临时工作。

补充已有日报时先用 `list_my_drafts` 定位，明确 ID 后通过 `get_my_draft` 读取目标内容、条目 ID、版本及可编辑性，必要时续读。`update_draft` 用 `changes` 的 `add` / `update` / `remove` 修改条目，并传 `expectedVersion`；省略字段保留原值，显式 `null` 清除可空关联。只改用户指定内容，保留未涉及条目及附件；带附件条目的删除转至网页。

保存草稿不会提交，也不会执行 `newTask` 或 `statusChange` 意图；报告“草稿已保存”。自然语言中的“完成了某工作”可写进正文，但只有明确要求同步任务状态时才设置 `statusChange`。

## 提交

使用 `submit_diary`，需要 `diaries:submit`；从头创建并提交还需要 `drafts:write`。草稿含新建任务或状态变更意图时还需要 `tasks:write`，以实际草稿为准，不为通过权限检查而删掉这些意图。

使用明确日报 ID 和当前草稿版本；可从刚完成的写回执取得，没有可用版本且无读取能力时说明缺失信息或能力。涉及已有任务状态变更时，意图中的 `expectedVersion` 也必须来自该任务已读版本。

首次提交按服务器北京时间当天确定日报日期；跨日草稿归入实际提交日，不能回填过去日期。已提交日报只在首次提交当天允许修改和重提，再次提交保持原日期。

提交中的日报发布、新建任务和状态更新在同一事务内成功或失败。成功后内容进入团队与项目阅读，并更新既有公开页；失败不能声称已部分提交。创建草稿和提交是两个独立调用，提交失败时已创建草稿可能仍保留，应告知用户其 ID。

## 独立任务操作

需要 `tasks:write`。`create_task` 在明确项目下创建待开始任务，必需参数以实际 schema 为准；项目关联不能猜测。

`update_task_status` 传明确任务 ID、目标状态和当前版本。通常先用 `get_task` 读取版本（需要 `progress:read`）；目标状态映射为待开始 `pending`、进行中 `in-progress`、已完成 `done`。独立状态更新不生成日报，会改变已有公开任务模块的当前状态，但不改历史日报中的状态快照。

共用 SKILL.md 的幂等和冲突规则；版本更新不是自动覆盖旧意图的许可。
